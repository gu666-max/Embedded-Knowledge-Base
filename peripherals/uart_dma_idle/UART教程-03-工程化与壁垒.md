## 第十一章 环形缓冲与零拷贝

### 11.1 为什么必须有环形缓冲

DMA/中断是**生产者**（来得快、时间不可控），应用是**消费者**（处理慢、可能被别的任务打断）。两者速率不匹配，中间必须有一个解耦的队列。

**环形缓冲的唯一价值**：ISR 里只做 O(1) 的入队，绝不因为数据量大小而变慢。

### 11.2 单生产者单消费者无锁队列

```c
#define RING_SIZE 256u                    /* 必须是 2 的幂 */
typedef struct {
    volatile uint32_t head;               /* 消费者读位置 */
    volatile uint32_t tail;               /* 生产者写位置 */
    uint8_t buf[RING_SIZE];
} ring_t;

/* 只在 ISR 里调用（单生产者） */
static inline bool ring_push(ring_t *r, uint8_t c)
{
    uint32_t t = r->tail;
    uint32_t n = (t + 1u) & (RING_SIZE - 1u);
    if (n == r->head) return false;       /* 满 */
    r->buf[t] = c;
    __DMB();                              /* 保证数据写入先于索引更新 */
    r->tail = n;
    return true;
}

/* 只在主循环里调用（单消费者） */
static inline bool ring_pop(ring_t *r, uint8_t *c)
{
    uint32_t h = r->head;
    if (h == r->tail) return false;       /* 空 */
    __DMB();
    *c = r->buf[h];
    r->head = (h + 1u) & (RING_SIZE - 1u);
    return true;
}
```

### 11.3 为什么它能不加锁（这是面试常问）

- **只有一个写者（ISR）和一个读者（主循环）**
- 写者只改 `tail`，读者只改 `head`，**没有共享的可写变量**
- 索引是 32 位对齐的字，单次读写是原子的（Cortex-M 上对齐的 32 位访问不会撕裂）
- `__DMB()` 防止编译器/CPU 把"写数据"和"更新索引"重排

**三个前提缺一不可**：单生产者、单消费者、索引更新在数据之后。

### 11.4 为什么 ISR 里不 memcpy

| 做法 | 时间 | 风险 |
|---|---|---|
| 逐字节入队（O(1)/字节） | 恒定 ~10 周期 | 低 |
| 一帧 memcpy 200 字节 | 200~600 周期，随长度变 | 高（可能丢下一字节） |

DMA 场景下更优的第三种做法：**零拷贝**——ISR 只记录"这半块缓冲属于哪一帧"，把指针交给上层，等上层处理完再归还。

## 第十二章 状态机与错误恢复

### 12.1 五个状态

```
        ┌──────────┐  收到字节   ┌────────────┐
        │   IDLE   │────────────>│  RX_ACTIVE │
        └──────────┘             └────────────┘
              ↑                        │ IDLE
              │                        ↓
        ┌──────────┐  处理完   ┌────────────┐
        │  RECOVER │<──────────│ FRAME_READY│
        └──────────┘  超时/错误 └────────────┘
              │
              ↓ 重新初始化
        ┌──────────┐
        │  ERROR   │
        └──────────┘
```

### 12.2 错误策略表（这一张表就是 L3 的全部内容）

| 错误 | 已损失什么 | 检测 | 恢复 | 上报 |
|---|---|---|---|---|
| ORE | 1 个字节 | SR.ORE | 清标志，丢弃当前帧 | 错误计数 + 帧丢弃计数 |
| FE | 当前字节 | SR.FE | 丢弃当前帧（帧肯定坏了） | 计数 |
| NE | 可能 0~1 字节 | SR.NE | 标记"可疑"，交给上层校验 | 计数 |
| DMA 传输错误 | 不确定 | DMA 错误标志 | 关闭 → 清标志 → 重配 → 重启 | 计数 + 上报 |
| 帧超时 | 无 | 定时器 | 丢弃半帧 | 计数 |
| 总线持续低（断线） | 全部 | RX 连续低 / 长时间无 IDLE | 重新初始化 + 降级 | 告警 |

**关键设计原则**：**每个错误都必须有"上报"这一格**。没有上报的错误 = 静默错误 = 最难查的 bug。

### 12.3 恢复要能被测量

不要写"能恢复"这种结论，要写"拔线 10 次，10 次都在 12 ms 内恢复，平均 8.3 ms"。

## 第十三章 core / port 分层与 PC 端单元测试

### 13.1 为什么要分层

不是为了"优雅"，是为了**能在没有硬件的情况下验证逻辑**。

```
driver/
├─ uart_core.c        ← 判帧、状态机、缓冲、错误策略（平台无关）
├─ uart_port.h        ← 契约（见本目录 driver/uart_port.h）
└─ uart_port_stm32f4.c← 寄存器/DMA/中断（平台相关）
```

**判定标准**：core 里出现 `USART2`、`GPIOA`、`HAL_`、`stm32` 任一字符 → 分层失败。

```

```

### 13.3 三个必写用例

| 用例 | 输入 | 期望 |
|---|---|---|
| 正常帧 | 8 字节 + IDLE | 取出 1 帧，长度 8 |

## 第十四章 帧协议层：从"收到字节"到"拿到对象"

### 14.1 四种分帧方式的选择

| 方式 | 优点 | 缺点 | 典型协议 |
|---|---|---|---|
| 固定长度 | 最简单、最快 | 不灵活 | 传感器定长帧 |
| 分隔符 | 可读性好 | 需转义 | AT 指令、NMEA |
| 长度字段 | 高效 | 需先读头 | 自定义二进制协议 |
| 时间间隔 | 无需额外字段 | 依赖时间精度 | Modbus RTU、DMX |

### 14.2 Modbus RTU 的 3.5 字符

- 字符 = 11 位（1 起始 + 8 数据 + 1 校验 + 1 停止）
- 9600 下一个字符 ≈ 1.146 ms → 3.5 字符 ≈ **4.0 ms**
- 规范要求帧间静默 ≥3.5 字符，帧内间隔 >1.5 字符视为错误

**与 IDLE 的关系**（必须讲清楚）：

```
IDLE 触发点（硬件，1 字符）
      ↓
      如果这是 Modbus，此时只能确认"至少 1 字符的静默"
      还需软件定时器再等 2.5 字符，才是合规的 3.5T
```

**工程折中**：很多设备直接用 IDLE 当帧结束，因为主站发完就等应答，帧内不会出现长间隔。**但这在"主站连续广播"时会粘帧**——这就是为什么现场有的设备偶尔解析错。

### 14.3 CRC16（Modbus）

```c
uint16_t modbus_crc16(const uint8_t *p, uint32_t len)
{
    uint16_t crc = 0xFFFFu;
    while (len--) {
        crc ^= *p++;
        for (int i = 0; i < 8; i++)
            crc = (crc & 1u) ? (uint16_t)((crc >> 1) ^ 0xA001u) : (uint16_t)(crc >> 1);
    }
    return crc;   /* 注意：Modbus 线上是低字节先发 */
}
```

## 第十五章 性能测量与取舍

### 15.1 用 DWT 测周期（不用示波器也能测）

```c
static inline void dwt_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CYCCNT = 0;
    DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
}
static inline uint32_t dwt_cycles(void) { return DWT->CYCCNT; }
```

```c
uint32_t t0 = dwt_cycles();
uart_poll();
uint32_t dt = dwt_cycles() - t0;      /* 周期数，除以 168e6 得秒 */
```

### 15.2 三种方式的对比表（作业要填满）

| 指标 | 轮询 | 中断 | DMA + IDLE |
|---|---|---|---|
| CPU 占用 @115200 | | | |
| CPU 占用 @921600 | | | |
| 最大可靠吞吐 | | | |
| 帧延迟（最小/典型/最坏） | | | |
| 代码量（行） | | | |
| 抗抢占能力 | 差 | 中 | 好 |

### 15.3 怎么选（这是 L5 的判断力）

- **调试口、低频命令** → 轮询最省事
- **中低速、帧短、CPU 空闲** → 中断足够
- **高速、变长帧、系统里有别的实时任务** → DMA + IDLE
- **要求确定性延迟** → 别用 UART，换 SPI/CAN

> 面试最爱问："你为什么用 DMA？" 错误回答："因为快。" 正确回答："因为中断延迟不可控，DMA 把每字节一次的中断降到每帧一次，把 CPU 占用从 8% 降到 0.3%，代价是判帧复杂度和 512 B RAM。"

## 第十七章 系统互扰

### 17.1 三类典型互扰

| 来源 | 机制 | 现象 |
|---|---|---|
| SD 卡 / Flash 写入 | 长时间占用总线 + 关中断 | 丢字节、ORE |
| PWM / 电机 | 电源噪声 + 地弹 | 随机 FE/NE |
| 高优先级中断 | 抢占 UART ISR | 高波特率 ORE |

### 17.2 先画 DMA 冲突矩阵

```
         Stream0 1 2 3 4 5 6 7
DMA1
DMA2
```

把每个外设占用的流标上去。**两个外设抢同一个流 = 必须有一个改方案**（换串口、换通道、或分时）。这个矩阵比任何文档都直观。

### 17.3 优先级设计原则

- UART RX 的 DMA 中断：**高**（防溢出）
- UART IDLE 中断：**中**（晚一点没关系，只是判帧延迟）
- 应用层解析：**最低**（主循环）
- **不要**把 UART 中断设成比控制环还高——会破坏实时性

| 寄存器 | 关键位 |
|---|---|
| `SR` | PE(0) FE(1) NF(2) ORE(3) IDLE(4) RXNE(5) TC(6) TXE(7) |
| `DR` | 写=发送；读=接收 |
| `BRR` | [15:4] 整数,[3:0] 小数（OVER8=1 时 [2:0]） |
| `CR1` | UE(13) M(12) PCE(10) PS(9) PEIE(8) TXEIE(7) TCIE(6) RXNEIE(5) IDLEIE(4) TE(3) RE(2) |
| `CR2` | STOP[13:12] LINEN(14) CLKEN(11) |
| `CR3` | CTSE(9) RTSE(8) DMAR(6) DMAT(7) EIE(0) |

> F7/H7/L4：SR → `ISR`（只读）/`ICR`（写 1 清零）/`RQR`（发请求）。不要混用。

## 附录 B：HAL 对照（万一要用 CubeMX）

| 寄存器写法 | HAL 对应 |
|---|---|
| 配 BRR + CR1 | `HAL_UART_Init()` |
| RXNE 中断接收 | `HAL_UART_Receive_IT()` |
| DMA 定长接收 | `HAL_UART_Receive_DMA()` |
| **DMA + IDLE 判帧** | `HAL_UARTEx_ReceiveToIdle_DMA()` |
| 判断错误 | `HAL_UART_GetError()` / `HAL_UART_ErrorCallback()` |

> HAL 的 `ReceiveToIdle_DMA` 内部就是"IDLE + NDTR"，理解原理后用它不算黑盒。

## 附录 C：20 个常见坑

1. 忘开 GPIO/USART 时钟 → 静默失败
2. TX/RX 没交叉
3. 没共地 → 乱码
4. BRR 直接写了 USARTDIV（差 16 倍）
5. APB1/APB2 搞混，照抄别人的 BRR
6. 只读 DR 清 ORE → 中断风暴
7. ISR 里 printf → 丢字节
8. 用 TXE 判断发送完成 → RS485 截断
9. RX 脚悬空 → 持续收 0x00
10. DMA 缓冲放 CCM → 收不到
11. DMA 配置时没等 EN 清零 → 改不动
12. 循环模式直接用 NDTR 算总长 → 跨圈算错
13. IDLE 当 3.5T 用 → 广播时粘帧
14. 帧缓冲 ≤ 最大帧长 → 溢出
15. 没做超时 → 半帧永远等下去
16. 中断优先级比控制环高 → 抖动
17. 多外设抢同一 DMA 流 → 其中一个静默失效
18. 波特率用 HSI → 跑热了出错
19. 唤醒后直接收 → 首字节丢
20. 所有错误都不上报 → 现场无法定位

## 附录 D：调试检查清单（没输出时按顺序查）

```
□ 1. 时钟使能了吗（GPIO / USART / DMA）？
□ 2. 引脚 AF 号对吗（USART2 = AF7）？
□ 3. TX/RX 交叉了吗？共地了吗？
□ 4. 对端波特率/帧格式一致吗？
□ 5. 用示波器看 TX 有没有波形？（没有 → 前 4 项）
□ 6. 有波形但乱码 → 波特率/时钟源
□ 7. 单字节能收、多字节丢 → ORE / 中断优先级
□ 8. DMA 收不到 → DMAR 位、流通道、EN 时序
□ 9. 能收但切不开帧 → IDLE 中断使能、NDTR 换算
□ 10. 偶尔错一帧 → 看 FE/NE 计数，查干扰与终端电阻
```
