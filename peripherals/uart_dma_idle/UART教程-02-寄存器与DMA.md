## 第五章 寄存器地图

### 5.1 F4 的 USART 寄存器（只有 7 个）

| 寄存器 | 作用 | 你会用到的位 |
|---|---|---|
| `SR` | 状态 | TXE, TC, RXNE, ORE, IDLE, FE, NE, PE |
| `DR` | 数据 | 写=发送，读=接收（**同一个地址，两个方向**） |
| `BRR` | 波特率 | 12 位整数 + 4 位小数 |
| `CR1` | 主控制 | UE, TE, RE, RXNEIE, TCIE, IDLEIE, PEIE, M, PCE, PS, OVER8 |
| `CR2` | 停止位/时钟 | STOP[1:0], LINEN, CLKEN |
| `CR3` | 流控/DMA | DMAR, DMAT, RTSE, CTSE, EIE |
| `GTPR` | 智能卡 | 一般不用 |

> **平台差异**：F7/H7/L4/U5 把 SR 拆成了 `ISR`（只读）+ `ICR`（只写，清标志），还多了 `RQR`（发请求）。F4 没有 ICR，只能用"读 SR 再读/写 DR"的序列清标志。**面试问"怎么清 ORE"，答错平台会当场露馅。**
>
> 你 project1 是 F407，所以本篇全按 F4 写。

### 5.2 最小初始化（USART2，PA2/PA3，115200 8N1）

```c
/* 1. 开时钟：GPIOA 在 AHB1，USART2 在 APB1 */
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
RCC->APB1ENR |= RCC_APB1ENR_USART2EN;

/* 2. PA2 = TX, PA3 = RX，都设为复用功能 AF7 */
GPIOA->MODER   &= ~((3u << (2*2)) | (3u << (3*2)));
GPIOA->MODER   |=  ((2u << (2*2)) | (2u << (3*2)));
GPIOA->AFR[0]  &= ~((0xFu << (2*4)) | (0xFu << (3*4)));
GPIOA->AFR[0]  |=  ((7u << (2*4)) | (7u << (3*4)));
GPIOA->OSPEEDR |=  ((3u << (2*2)) | (3u << (3*2)));   /* very high */
/* 接收脚上拉：线悬空时不会收到一堆噪声 0 */
GPIOA->PUPDR   &= ~(3u << (3*2));
GPIOA->PUPDR   |=  (1u << (3*2));

/* 3. 波特率：42MHz / 115200 = 22.7865 → BRR = 365 (0x16D) */
USART2->BRR = 365;

/* 4. 最后开 UE，并且只开你要的方向 */
USART2->CR1 = USART_CR1_UE | USART_CR1_TE | USART_CR1_RE;
```

**四个必须理解的点：**

1. **`UE` 必须最后置位**。提前开 UE 时，如果 BRR 还是 0，会立刻产生错误状态。
2. **`TE`/`RE` 是分开的**。只发不收就只开 TE，能减少无意义的中断。
3. **PA3 上拉不是可选项**。RS485 收发器在接收态才驱动总线；如果 DE 控制错了或没接从机，RX 悬空会持续收到 0x00。
4. **`DR` 是同一地址的双向口**。读 DR 清 RXNE，写 DR 启动发送——这个"同址双向"是所有清除序列坑的根源。

> 为什么这里不用 `M` 位（数据位宽）？因为默认 `M=0` 就是 8 位。这就是"默认值也是配置"——你必须知道它默认是 8 位，而不是"没配就是 8 位"。

### 5.3 破坏实验（作业的一部分，先看做法）

| 改什么 | 预期现象 | 为什么 |
|---|---|---|
| 不置 `UE` | 写 DR 没反应 | 外设没使能，寄存器写入被忽略 |
| `AFR` 设成 AF5 | 完全收不到 | 引脚没连到 USART，信号去了别的外设 |
| 忘开 `GPIOAEN` | 引脚配置静默失败 | 时钟没开，写寄存器无效，**不报错** |
| `BRR` 改成 730 | 对端全是乱码 | 波特率差 2 倍，采样点全错 |

**"静态失败"是最危险的失败**：外设时钟没开时写寄存器不报错、不崩溃，就是没效果。这就是为什么第五章的作业里要求你逐位注释——你要能一眼看出"缺了哪个使能"。

## 第六章 标志位与清除顺序（ORE 的坑）

### 6.1 状态位速查

| 位 | 含义 | 什么时候置位 | 怎么清（F4） |
|---|---|---|---|
| `TXE` | 发送寄存器空 | DR 里的数据搬进移位寄存器 | 写 DR |
| `TC` | 发送完成 | 最后一个停止位发完 | **读 SR 再写 DR** |
| `RXNE` | 收到一个字节 | DR 里有新数据 | **读 DR** |
| `ORE` | 溢出 | 新字节来了但 DR 还没被读走 | **读 SR 再读 DR** |
| `IDLE` | 总线空闲 | 检测到 ≥1 帧时间的空闲 | **读 SR 再读 DR** |
| `FE` | 帧错误 | 停止位不是 1 | 读 SR 再读 DR |
| `NE` | 噪声 | 采样时检测到多位不一致 | 读 SR 再读 DR |
| `PE` | 校验错 | 校验位不符 | 读 SR 再读 DR |

**记忆口诀**：**"先读 SR，再动 DR"**——除了 TXE 和 RXNE 这两个"正常路径"的标志，其余全部靠这个序列清。

### 6.2 ORE 的真相

ORE 不是"数据丢了"的预防，是"数据已经丢了"的事后通知。

```
字节 N     字节 N+1
  ↓           ↓
[DR = N]  [移位寄存器收到 N+1，但 DR 里还是 N]
              ↓
         ORE = 1，N+1 被丢弃
```

**关键结论**：
- ORE 置位时，**新收到的字节已经丢了**，你救不回来
- 你唯一能做的是：清 ORE，记录一次错误，然后继续
- 如果不清，ORE 会一直挡着，后面每个字节都丢

### 6.3 经典错误写法

```c
/* ❌ 错误：只读 DR，ORE 永远清不掉 */
uint8_t c = USART2->DR;
```

```c
/* ✅ 正确：先读 SR 快照，再读 DR */
uint32_t sr = USART2->SR;
uint8_t  c  = USART2->DR;
if (sr & USART_SR_ORE) { err_count++; }
```

为什么必须先读 SR？因为**读 DR 会连同 RXNE 一起清掉**，而 ORE 的清除需要"SR 已读 + DR 已读"这个组合。只读 DR，ORE 位保持，下一次进中断还是同一个错误，形成"中断风暴"。

> 面试延伸："ORE 之后你还能收到数据吗？" 答：清掉 ORE 后可以，但丢的那个字节永久丢失；如果对端连续发，你还会继续丢——所以恢复策略必须包含"告知对端重传或整帧丢弃"。

## 第七章 中断接收

### 7.1 最小中断接收

```c
void uart_rx_irq_enable(void)
{
    NVIC_SetPriority(USART2_IRQn, 5);
    NVIC_EnableIRQ(USART2_IRQn);
    USART2->CR1 |= USART_CR1_RXNEIE;
}

void USART2_IRQHandler(void)
{
    uint32_t sr = USART2->SR;          /* 先快照，后面判断都基于它 */
    if (sr & (USART_SR_RXNE | USART_SR_ORE | USART_SR_FE | USART_SR_NE)) {
        uint8_t c = (uint8_t)USART2->DR;   /* 读 DR 同时清 RXNE/ORE/FE/NE */
        if (sr & (USART_SR_ORE | USART_SR_FE | USART_SR_NE)) {
            uart_err_flags |= (sr & (USART_SR_ORE|USART_SR_FE|USART_SR_NE));
            return;                         /* 出错字节不写进缓冲 */
        }
        ring_push(&rx_ring, c);             /* 只做入队，不做别的 */
    }
}
```

### 7.2 ISR 里绝对不能做的事

| 禁止 | 原因 | 替代 |
|---|---|---|
| `printf` / 字符串格式化 | 可能阻塞几百 µs，直接丢字节 | 置标志，主循环打印 |
| `malloc` | 堆操作不可重入、时间不确定 | 静态缓冲 |
| 等某个标志（`while(...)`） | 中断里等中断，死锁 | 状态机 |
| 大块 `memcpy` | 占用时间随长度增长 | 只记录偏移，让 DMA 搬 |
| 浮点运算（有 FPU 但未保存上下文） | 可能破坏其它任务的浮点寄存器 | 定点/查表 |

### 7.3 中断方式到底扛不扛得住（算给它看）

以 168 MHz、ISR 约 150 个周期估算：

| 波特率 | 每字节间隔 | 可用周期 | ISR 占比 | 结论 |
|---|---|---|---|---|
| 9600 | 1.04 ms | 175,000 | ~0.09% | 随便用 |
| 115200 | 86.8 µs | 14,600 | ~1.0% | 舒服 |
| 921600 | 10.85 µs | 1,820 | ~8.2% | 开始危险 |
| 2 M | 5.0 µs | 840 | ~18% | 一旦有更高优先级中断就丢 |

> 这个表是**估算**，作业里要你实测。差值就是你的"中断延迟 + 其它中断插队"。

**为什么高波特率会丢**：不是因为 ISR 太长，而是因为**ISR 可能被更高级的中断推迟**。UART 没有硬件缓冲深度（F4 只有 1 字节 DR + 1 字节移位寄存器），推迟超过 1 个字节时间就 ORE。

## 第八章 DMA 接收

### 8.1 DMA 解决的不是"快"，是"确定性"

中断方式的问题是**延迟不可控**（被抢占）。DMA 把"搬运"从 CPU 手里拿走，CPU 只需要在"一帧结束"时被通知一次。

| | 轮询 | 中断 | DMA |
|---|---|---|---|
| CPU 参与频率 | 每字节 | 每字节 | 每帧（甚至更少） |
| 延迟敏感 | 是 | 是 | 否（硬件缓冲） |
| 最大可靠速率 | 低 | 中 | 高 |
| 代码复杂度 | 低 | 中 | 高（配置 + 判帧） |

### 8.2 F407 的 DMA 请求映射（必须查表，不许背）

| 串口 | RX 流/通道 | TX 流/通道 |
|---|---|---|
| USART1 | DMA2 Stream2 Ch4 / Stream5 Ch4 | DMA2 Stream7 Ch4 |
| USART2 | DMA1 Stream5 Ch4 | DMA1 Stream6 Ch4 |
| USART3 | DMA1 Stream1 Ch4 | DMA1 Stream3 Ch4 |
| UART4 | DMA1 Stream2 Ch4 | DMA1 Stream4 Ch4 |
| UART5 | DMA1 Stream0 Ch4 | DMA1 Stream7 Ch4 |
| USART6 | DMA2 Stream1 Ch5 / Stream2 Ch5 | DMA2 Stream6 Ch5 |

> **以 RM0090 表 43 / 44 为准。** 这张表我凭记忆写，你作业里必须核对一遍——这正是"不许凭记忆"的示范。

### 8.3 配置代码（USART2 RX，循环模式）

```c
#define RX_BUF_LEN 128
static uint8_t rx_buf[RX_BUF_LEN];

void uart_dma_rx_start(void)
{
    RCC->AHB1ENR |= RCC_AHB1ENR_DMA1EN;

    DMA1_Stream5->CR &= ~DMA_SxCR_EN;
    while (DMA1_Stream5->CR & DMA_SxCR_EN) { }      /* 必须等 EN 真正清零 */

    DMA1->HIFCR = 0x3F0000u;                         /* 清 Stream5 全部标志 */

    DMA1_Stream5->PAR  = (uint32_t)&USART2->DR;      /* 外设地址 */
    DMA1_Stream5->M0AR = (uint32_t)rx_buf;           /* 内存地址 */
    DMA1_Stream5->NDTR = RX_BUF_LEN;                 /* 要搬多少个 */

    DMA1_Stream5->CR = (4u << DMA_SxCR_CHSEL_Pos)    /* 通道 4 */
                     | DMA_SxCR_MINC                 /* 内存地址自增 */
                     | DMA_SxCR_CIRC                 /* 循环模式 */
                     | DMA_SxCR_PL_1;                /* 高优先级 */

    DMA1_Stream5->CR |= DMA_SxCR_EN;
    USART2->CR3      |= USART_CR3_DMAR;              /* 让 USART 发 DMA 请求 */
}
```

**三个容易错的点：**

1. **必须先等 `EN` 清零再改配置**。EN=1 时改 NDTR/PAR 会被静默忽略。
2. **`MINC` 只加内存地址**，外设地址固定为 `&DR`，所以 `PINC` 不能开。
3. **`DMAR` 是 USART 侧的开关**。DMA 流开了但 USART 不发请求，一样收不到。

### 8.4 NDTR 是唯一能告诉你"收了多少"的东西

```
已收字节数 = 缓冲长度 − NDTR
```

循环模式下 NDTR 会从满减到 0 再回到满。所以**不能只用一次差值**判断总量，必须维护一个"绝对计数"或"上次位置"，否则跨圈时会算错。

### 8.5 两个 F407 专属的坑

**坑一：CCM RAM 不能被 DMA 访问。**
F407 有 64 KB CCM（地址 0x10000000），只有 CPU 能访问。把 `rx_buf` 放进 CCM，DMA 会静默搬 0 或者触发总线错误。

```c
/* ❌ 这样定义，DMA 读不到 */
static uint8_t rx_buf[RX_BUF_LEN] __attribute__((section(".ccmram")));
/* ✅ 放普通 SRAM */
static uint8_t rx_buf[RX_BUF_LEN];
```

**坑二：F407 没有 D-Cache，所以"Cache 一致性"这个问题在 F4 上不存在。**
但你在 H7 上一定会撞到：DMA 写入内存，CPU 读到的是 Cache 里的旧值。到时候需要 `SCB_CleanInvalidateDCache_by_Addr()` 或把缓冲区配成 non-cacheable。**知道"哪个平台有这个问题"本身就是深度。**

## 第九章 IDLE 判帧（本篇核心）

### 9.1 问题：DMA 不知道帧在哪结束

DMA 只知道"搬了多少字节"，不知道"这一帧结束了"。所以变长帧必须靠**时间间隔**判断边界——这就是 IDLE。

**IDLE 的硬件定义**：接收线在最后一个停止位之后，保持空闲（高电平）达到 **1 个完整帧时间**，硬件置 `IDLE`。

```
数据 ... 停止位 ────── 空闲 ≥1 帧 ────── 下一帧起始
                    ↑
                 IDLE 置位（UART 认为"这一段话讲完了"）
```

### 9.2 为什么它是变长帧的标准解法

| 方案 | 适用 | 问题 |
|---|---|---|
| 固定长度 | 定长协议 | 长度一变就废 |
| 分隔符（如 `\n`） | 文本协议 | 数据里出现分隔符就断错 |
| 长度字段 | 带帧头的二进制协议 | 需要先读头再读体，两段式 |
| **IDLE 间隔** | 任何"一问一答/突发"的协议 | 帧间间隔太短会粘连 |

Modbus RTU 用的就是"间隔"，只不过它规定的是 **3.5 个字符时间**，而 STM32 的 IDLE 只有 **1 个字符时间**——这是第九章最重要的认知：

> **硬件 IDLE ≠ Modbus 3.5T。**
> 用 IDLE 收到的"帧"，可能只是 Modbus 帧的一段。要做严格 Modbus，必须在 IDLE 之后再叠加一个定时器判断。

### 9.3 实现骨架

```c
#define RX_BUF_LEN 256
static uint8_t  rx_buf[RX_BUF_LEN];
static volatile uint32_t frame_len;
static volatile uint32_t frame_tick;
static volatile bool     frame_ready;

void USART2_IRQHandler(void)
{
    uint32_t sr = USART2->SR;

    if (sr & USART_SR_IDLE) {
        (void)USART2->DR;                        /* 读 SR 后读 DR，清 IDLE */
        uint32_t remain = DMA1_Stream5->NDTR;
        uint32_t n      = RX_BUF_LEN - remain;
        if (n > 0) {
            frame_len   = n;
            frame_tick  = now_ms();
            frame_ready = true;                  /* 只置标志，不搬数据 */
        }
        /* 循环模式不用重启 DMA；Normal 模式这里要重新 arm */
    }

    if (sr & (USART_SR_ORE | USART_SR_FE | USART_SR_NE)) {
        (void)USART2->DR;
        uart_err_flags |= (sr & (USART_SR_ORE|USART_SR_FE|USART_SR_NE));
    }
}
```

### 9.4 三种边界（必须全部处理）

| 边界 | 现象 | 处理 |
|---|---|---|
| **背靠背帧**（间隔 <1 字符） | 两帧粘成一帧 | 上层按协议再切分；或降低发送端速率 |
| **超长帧**（> 缓冲） | 缓冲被覆盖，NDTR 绕圈 | 检测 `n == 0` 且数据在动 → 丢弃并报错 |
| **零长度** | 只有噪声触发了 IDLE | 忽略 `n == 0` |

### 9.5 最短可分辨间隔是多少？

这不只是"1 字符时间"，而是：

$$\text{最短间隔} \approx \max(1\ \text{字符时间},\ \text{ISR 响应时间} + \text{上半部处理时间})$$

115200 下 1 字符 = 86.8 µs。如果你的 ISR 被高优先级中断推迟了 100 µs，那么实际能分辨的间隔就 >100 µs，而不是 86.8 µs。**这就是为什么要实测。"标称值"和"你的系统能做的值"永远是两回事。**

| 对比"理论 86.8 µs"与你的实测，解释差在哪 | 结论 |
| 加时间戳，统计帧间隔分布 | 直方图或表格 |

**验收**：能说出"我的系统在 115200 下能可靠分辨 ≥X µs 的帧间隔"，并给出证据。

## 第十章 低功耗与唤醒

### 10.1 STOP 模式下的 UART

F4 在 STOP 模式主时钟停振，USART 靠 **起始位检测** 唤醒 MCU。流程：

```
停止位 ... 空闲 ─── 下降沿(起始位) ───► USART 产生唤醒事件 ──► MCU 退出 STOP
```

### 10.2 首字节为什么会丢

从"检测到起始位"到"CPU 真正跑起来"，中间有：

- 时钟恢复时间（HSI 起振，手册给的是 µs 级）
- 中断向量取指、上下文恢复
- 你的时钟初始化代码

**而一个字节只要 86.8 µs（115200）或 1.04 ms（9600）。** 所以：

- **9600 下大概率不丢**（时间够）
- **115200 下几乎必丢**（来不及）

### 10.3 三种补偿方案

| 方案 | 做法 | 代价 |
|---|---|---|
| 协议层容错 | 唤醒后先发一个"前导字节"，从机丢弃 | 浪费带宽 |
| 地址唤醒 | 用 USART 的 address mark 唤醒，只响应自己 | 需要 9 位数据模式 |
| 硬件唤醒 + 重发 | 主机收不到应答就重发 | 增加延迟 |

> 面试加分点："STOP 唤醒丢首字节不是 bug，是物理必然。工程上要么在协议里加前导码，要么让从机在收到唤醒后延迟一小段时间再发。"
