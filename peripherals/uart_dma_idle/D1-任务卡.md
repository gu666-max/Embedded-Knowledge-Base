## 交付物 1：帧级时序图（纸笔或 draw.io，拍/截图存 `evidence/`）

画一条 8N1、115200 的帧，标出：

```
空闲(高) ─┐        ┌─── D0 ─── D1 ... D7 ───┬── 停止位 ──┬─ 空闲 ─
          └─ 起始位(低) ─┘                   └────────────┘
```

必须标出这些**具体数字**（算出来，不要抄）：

| 项 | 公式 | 你的答案 |
|---|---|---|
| 1 位时间 | 1 / 波特率 | μs |
| 1 帧位数（8N1） | 1 起始 + 8 数据 + 1 停止 | 位 |
| 1 帧时间 | 位数 × 位时间 | μs |
| 连续收 100 字节需要 | 100 × 帧时间 | ms |
| IDLE 判定窗口 | 至少 1 个字符时间 | μs |

> 验收：如果卡在"1 位多少 µs"上，说明你还没把波特率的物理含义想清楚——这题必须自己算，不许查。

## 交付物 2：数据通路图

画一条从**引脚电平到应用缓冲区**的完整路径，每一跳都要标出"谁在动"：

```
RX 引脚电平
   ↓  (采样、移位：谁做的？在字节的第几位采样？)
接收移位寄存器
   ↓  (什么条件下搬走？)
RDR (接收数据寄存器)
   ↓  (谁触发搬运？)
DMA 请求
   ↓  (哪个流？哪个通道？内存地址谁给？地址怎么增？)
内存缓冲区
   ↓  (什么时候认为"这一帧收完了"？)
IDLE 中断
   ↓  (ISR 里只做什么？)
应用层取出
```

必须回答的 6 个问题（写在图旁边）：

1. STM32 在**一位中间的哪个位置**采样？（过采样 16 时采样点在第几位？）
2. 一个字节收完时，CPU 有没有"看到"过它？为什么 DMA 能绕过 CPU？
3. DMA 传输完成后，**怎么知道这一帧结束了**？为什么不能用"接收长度 = 固定值"？
4. IDLE 中断和 DMA 传输完成中断，哪个先发生？为什么？
5. 如果两帧之间间隔极短（<1 字符时间），会发生什么？
6. 如果应用层取数据比收数据慢，缓冲会在哪里溢出？怎么发现？

> 这 6 个问题就是 L1 的过关标志。答不上来的那条，就是你 D1 要去查的点（RM0090 §30 与 DMA 章节）。

## 交付物 3：波特率误差推导（一页）

不查工具，自己算一遍并留痕：

```
假设 USART1（APB2 = 84MHz），目标 115200 8N1：
USARTDIV = fCK / (16 × baud)
BRR = round(USARTDIV × 16)   ← 注意 BRR 直接编码 USARTDIV
实际波特率 = fCK / BRR
误差 = (实际 − 目标) / 目标

再算一次 USART2（APB1 = 42MHz），比较哪个更接近。
```

结论必须写成一句话，例如："两者误差都在 ±0.2% 内，工程上按 ≤2.5% 控制，均可用。"（具体数字自己算，别抄这句）
