> 嵌入式知识库：**一个外设 = 一个文件夹 = 一份可复用资产**。
>
> 目标不是"学过多少外设"，而是**有几个外设能被面试官追问到第五层**。

## 四条铁律

1. **广度决定上手，深度决定别人要不要你。** 只钻会反复用到的外设。
2. **深度 = 原理 + 实测数据 + 失效目录 + 可复用的验证手段。** 只有原理，答不上"你怎么验证的"。
3. **不背代码。** 写出来一次、理解原理、沉淀成资产；用时查自己的笔记或手册。
4. **同一时间只钻一个外设。** 其余最多是 🟡，否则就是变相的广度优先。

## 新增一个外设（标准流程）

1. 复制骨架：`peripherals/_模板/` → `peripherals/<外设名>/`
   - 命名：小写 + 下划线，用外设通用名，例：`dma`、`tim_pwm`、`adc_scan`、`uart_dma_idle`
2. 在下表登记开始日期与目标完成日
3. 按 [`docs/外设深钻方法论.md`](./docs/外设深钻方法论.md) 的 18 天时间盒推进（L1 → L6）
4. 状态改成 ✅ 之前，必须满足：波形 + 数字 + 故障注入 ≥8 项 + 3 分钟讲解录音

## 每个外设文件夹的规范

```
peripherals/<外设名>/
├─ README.md      ← 唯一入口：能力边界、参数理由、失效模式、验证结论
├─ notes/         ← 原理与推导、破坏实验、未解问题
├─ driver/        ← core（平台无关）+ port（平台相关）
├─ test/          ← 自检、压测、故障注入，能一键复现结论
└─ evidence/      ← 波形、实测数据、对比表、讲解录音
```

**准入条件**：README 能让别人直接接进去；`evidence/` 里至少一个波形 + 一组数字 + 一次故障注入。缺一条就是没沉淀完。

## 什么不要放进来

- 编译产物（`Objects/`、`*.o`、`*.axf`、`*.map`）——已在 `.gitignore` 里
- 未整理的资料堆（PDF 手册、教程截图）——放本地，仓库只放**结论**
- 别人的完整工程整包——要参考就抽成笔记，别搬进来
- `test1/`、`demo/`、`temp/`、`新建文件夹` 之类的目录

## 提交习惯

- 每次推进至少一次提交，message 写清「哪个外设 + 到哪一层 + 做了什么」
  - 例：`uart_dma_idle: L2 完成，补 IDLE 判帧与 ORE 清除顺序笔记`
- 半路放弃的，把状态改成 🧊，在 README 里写清「停在哪层、为什么停」
